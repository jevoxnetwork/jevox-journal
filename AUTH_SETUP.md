# Настройка входа в Jevox Journal

Рабочий сайт размещён на Cloudflare Pages. База учётных записей и сессий: Cloudflare D1.

## Адреса для рабочего сайта

Адрес сайта / Allowed Origin:

```
https://jevoxjournal.pages.dev
```

Telegram Redirect URI:

```
https://jevoxjournal.pages.dev/auth/telegram/callback
```

VK Redirect URI:

```
https://jevoxjournal.pages.dev/auth/vk/callback
```

Схема, домен, путь и завершающий слеш должны совпадать с зарегистрированными адресами. В этих Redirect URI завершающего слеша нет.

## Telegram

1. Создайте бота через официальный `@BotFather`.
2. В настройках входа переключитесь с устаревшего Login Widget на OpenID Connect Login.
3. Добавьте адрес сайта в Allowed URL / Trusted Origin, а полный адрес возврата — в Redirect URIs.
4. Получите **Client ID** и **Client Secret** из настроек OpenID Connect.
5. Оставьте алгоритм подписи **RS256** или выберите ES256. Сервер проверяет подписанный ID token, issuer, audience и срок действия. Поток Authorization Code привязан к браузеру через одноразовый state и серверный PKCE verifier; поле nonce от JS-виджета в нём не требуется.
6. В серверных переменных заполните `TELEGRAM_CLIENT_ID` и `TELEGRAM_CLIENT_SECRET`.

Токен Telegram-бота из `/newbot` не является Client Secret входа. Номер телефона и право отправлять сообщения не запрашиваются.

Официальная документация: https://core.telegram.org/bots/telegram-login

## ВКонтакте

1. Откройте кабинет VK ID: https://id.vk.ru/about/business/go
2. Создайте веб-приложение и добавьте домен сайта.
3. Зарегистрируйте указанный выше VK Redirect URI.
4. Заполните `VK_CLIENT_ID`. Если тип приложения требует конфиденциальный ключ, заполните также `VK_CLIENT_SECRET`.
5. Используется Authorization Code + PKCE. Сервер проверяет state, обменивает код с device_id и получает профиль через официальный `user_info`.

Официальный SDK и описание протокола: https://github.com/VKCOM/vkid-web-sdk

## Где хранить ключи

Рабочий проект Cloudflare Pages называется `jevoxjournal`. Привязка к базе D1 указана в `wrangler.pages.jsonc`.

Для локального запуска скопируйте `.env.example` в `.env` и заполните значения. Файл `.env` исключён из Git. Для Cloudflare установите секреты через Dashboard → Workers & Pages → jevoxjournal → Settings → Variables and Secrets. Изменение локального `.env` само по себе не меняет облако.

Также можно использовать `wrangler pages secret put <ИМЯ> --project-name jevoxjournal`. Вводите значения в интерактивный запрос, а не как аргументы команд.

Не вставляйте секреты в HTML, JavaScript клиента, скриншоты или переписку. Client Secret и необязательный VK secret должны быть отмечены как secrets в настройках Cloudflare. Параметры рабочего сайта задаются для окружения Production.

`PUBLIC_URL` в облаке должен равняться адресу рабочего сайта, без завершающего слеша. Для локального сервера используется `http://localhost:5173`; локальные callback требуют отдельной регистрации у провайдера и могут быть отклонены его настройками безопасности.

## Вход и должности сотрудников

Права определяет должность в таблице `moderators`. Привязка выполняется по числовому ID аккаунта в `telegram_id` или `vk_id`. При первоначальной настройке пустой базы добавьте первого владельца в D1 с подтверждённым ID. После этого владелец может добавлять сотрудников в «Управлении составом».

Списки `STAFF_TELEGRAM_IDS`, `STAFF_VK_IDS` и ранее использовавшиеся `ADMIN_TELEGRAM_IDS`, `ADMIN_VK_IDS` разрешают вход. Права на управление они не выдают. Новый аккаунт вне состава и этих списков получает статус `pending`. Telegram и VK не объединяются по совпадению имени.

## Что уже реализовано

- Серверные OAuth-потоки для двух провайдеров; PKCE и случайные одноразовые state.
- Одноразовые попытки входа, привязанные к браузеру, со сроком 10 минут.
- Сессии действуют 3 дня с момента входа. Каждый защищённый запрос требует cookie сессии и отдельный ключ браузера. В D1 сохраняются только их хеши. После удаления данных сайта или перехода в другой браузер нужно заново войти.
- HttpOnly / SameSite=Lax cookies; Secure и префикс `__Host-` на HTTPS.
- CSRF-защита выхода и изменений прав, ограничение попыток, серверный контроль доступа.
- Учётные записи, сессии, должности и события авторизации в D1.
- Данные журнала выдаются сервером только активному сотруднику с действительной сессией. Браузер получает сжатые JS и CSS без карт исходников.

## Discord-бот

Журнал хранит соответствие сотрудника и Discord по полю «ID Discord». При добавлении сотрудника это поле обязательно. Для старых записей ID добавляется через «Управление составом» → «Изменить».

Cloudflare Pages принимает подписанные команды Discord по пути `/api/discord/interactions`. Для проекта `jevoxjournal` в Production используются секреты `DISCORD_BOT_TOKEN` и `DISCORD_PUBLIC_KEY`. Worker `jevox-discord-presence` использует тот же `DISCORD_BOT_TOKEN`, подключается к Gateway со статусом `dnd` и повторяет отложенные операции с ролями. После сброса токена обновите его в обоих сервисах.

Роль бота должна стоять выше всех ролей из `worker/discord.mjs`. Боту нужны «Управлять ролями» и «Управлять никнеймами» на сервере и разрешения просматривать канал логов, отправлять сообщения и использовать встроенные ссылки. Команда `/sync` доступна участникам с ролью владельца. Если сотрудник уже в Discord, роль и серверный ник Discord синхронизируются после сохранения карточки. Событие входа в Discord запускает синхронизацию для привязанного сотрудника. Для события входа включите Server Members Intent в настройках Discord-приложения. Команда `/sync` сразу подтверждает постановку в очередь, а результат отправляется в канал логов.
