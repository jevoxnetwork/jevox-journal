# Jevox Journal

Журнал модерации Jevox Network с серверным входом через Telegram и VK ID. Сервер рассчитан на Cloudflare Workers; учётные записи и сессии сохраняются в D1. Интерфейс журнала построен по предоставленному референсу.

## Запуск

Требуется Node.js 24+. Из корня проекта выполните `npm ci`, затем `npm run build` и `npm start`. Адрес: `http://localhost:5173`. Для локальных параметров скопируйте `.env.example` в `.env`. Локальная база Miniflare хранится в `.wrangler/state/d1` и сохраняется между запусками.

Не запускайте папку `dist` как обычный статический сайт: обработка авторизации и контроль доступа выполняются Worker. Облачное развёртывание использует `dist/server/index.js` и миграции `drizzle`.

Полная инструкция по Telegram, VK, секретам и выдаче первого административного доступа: [AUTH_SETUP.md](AUTH_SETUP.md).

## Рабочий Cloudflare

https://jevoxjournal.pages.dev

Рабочий проект Cloudflare Pages называется `jevoxjournal`. Конфигурация проекта и привязки D1 `DB` находится в `wrangler.pages.jsonc`. Порядок сборки и обновления описан в [DEPLOY.md](DEPLOY.md).

## Возможности

- Рабочие вкладки: главная, проверки, состав, статистика и правила сервера.
- Личная история проверок и поиск по проверкам состава для менеджеров и выше. События записывает [FastFreeze](integration/fastfreeze/README.md).
- Настройки ника и адаптивная мобильная версия.
- Серверная авторизация, безопасный выход, отдельный доступ сотрудников и административное управление аккаунтами.

Авторизация и права сохраняются на сервере в D1. Вход через провайдеров станет доступен после настройки их реальных Client ID / Secret. Без них кнопки не имитируют успешную авторизацию.

Проверки безопасности: `npm test`. Сборка: `npm run build`. Новые миграции: `npm run db:generate` после изменения `db/schema.ts`. Применённые миграции не изменяются.
