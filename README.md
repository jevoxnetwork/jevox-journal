# Журнал модерации

Журнал модерации с серверным входом через Telegram и VK ID. Сервер рассчитан на Cloudflare Workers; учётные записи и сессии сохраняются в D1. Интерфейс журнала построен по предоставленному референсу.

## Запуск

Требуется Node.js 24+. Из корня проекта выполните `npm ci`, затем `npm run build` и `npm start`. Адрес: `http://localhost:5173`. Для локальных параметров скопируйте `.env.example` в `.env`. Локальная база Miniflare хранится в `.wrangler/state/d1` и сохраняется между запусками.

Не запускайте папку `dist` как обычный статический сайт: обработка авторизации и контроль доступа выполняются Worker. Облачное развёртывание использует `dist/server/index.js` и миграции `drizzle`.

Полная инструкция по Telegram, VK, секретам и выдаче первого административного доступа: [AUTH_SETUP.md](AUTH_SETUP.md).

## Рабочий Cloudflare

https://newcube-moderation-journal.1pirs.workers.dev

Worker развёрнут напрямую в Cloudflare-аккаунте владельца через `wrangler.jsonc`, без Sites и домена `chatgpt.site`. D1: `newcube-journal-auth`. Для обновления выполните `npm run deploy`; миграции применяются командой `wrangler d1 migrations apply newcube-journal-auth --remote --config wrangler.jsonc`. Остальные базы и Worker аккаунта не затрагиваются.

## Возможности

- Рабочие вкладки: главная, проверки, состав, статистика и правила сервера.
- Поиск внутри списка проверок, фильтры и просмотр деталей.
- Создание проверок и сохранение итогов.
- Экспорт проверок в CSV и статистической сводки.
- Настройки ника и адаптивная мобильная версия.
- Серверная авторизация, безопасный выход, отдельный доступ сотрудников и административное управление аккаунтами.
- Демонстрационные записи интерфейса пока хранятся локально с отдельным ключом на каждого вошедшего пользователя.

Авторизация и права сохраняются на сервере в D1. Записи проверок пока демонстрационные и не синхронизируются с Minecraft, LuckPerms, NModer, NCheck, NReport и LiteBans. Вход через провайдеров станет доступен после настройки их реальных Client ID / Secret. Без них кнопки не имитируют успешную авторизацию.

Проверки безопасности: `npm test`. Сборка: `npm run build`. Новые миграции: `npm run db:generate` после изменения `db/schema.ts`. Применённые миграции не изменяются.
